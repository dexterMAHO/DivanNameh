# تصمیم‌های پیاده‌سازی دیوان نامه

- نام برند: «دیوان نامه»، نام پروژه: `DivanNameh`.
- Django 5.2 LTS، Django Templates، Vanilla JS و SQLite در توسعه؛ PostgreSQL از طریق DATABASE_URL.
- سرویس Sites میزبان Worker/Static است و Python/Django را اجرا نمی‌کند؛ این پروژه در پوشهٔ محلی پیاده‌سازی شده و برای VPS آماده می‌شود.
- ورودی تمام endpointهای POST فرم استاندارد URL-encoded یا multipart است. `Accept: application/json` پاسخ JSON می‌دهد. JSON request body پشتیبانی نمی‌شود؛ این انتخاب مجاز قرارداد سند است.
- ابیات دارای شناسهٔ پایدارند. در ویرایش فقط اصلاح متن و افزودن به انتها مجاز است؛ حذف و تغییر ترتیب در MVP پشتیبانی نمی‌شود.
- تگ تازه در فرم شعر هنگام ذخیرهٔ اتمیک ایجاد و به شعر منتسب می‌شود؛ تگ‌های موجود جست‌وجوی محلی دارند.
- API کشف برای کتابخانهٔ خالی `200` و `poem: null` می‌دهد.
- تراکنش‌های SQLite با `IMMEDIATE` آغاز می‌شوند تا نویسندگان همزمان سری شوند. PostgreSQL از قفل شعر و سپس کارت استفاده می‌کند. UUID یکتا و retry محدود در ثبت مرور داریم.
- مرور با details بومی HTML آشکار می‌شود؛ بدون JavaScript نیز پاسخ و امتیازها با بازکردن آن در دسترس‌اند. JS امتیازها را قبل از reveal غیرفعال می‌کند.
- پنل مدیریت داده‌های شعر و مرور فقط برای مشاهده توسط superuser است؛ اصلاح داده از UI اصلی انجام می‌شود تا invariantها و بازنشانی مرور دور زده نشوند. مدیریت کاربران از Django Admin در دسترس است.
- تاریخ‌ها میلادی و بر اساس Asia/Tehran نمایش داده می‌شوند؛ تقویم جلالی خارج از الزام MVP است.
- فونت‌های Vazirmatn و Noto Naskh Arabic از google/fonts، با فایل مجوز OFL و میزبانی محلی.
- هیچ دادهٔ نمایشی یا حساب با رمز ثابت در نصب اصلی ساخته نمی‌شود؛ حساب اولیه با createsuperuser ساخته می‌شود.
